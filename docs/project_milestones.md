# FaithLog 專案里程碑規劃

## 專案概述

**FaithLog** 是一個聖經讀經 + 小遊戲的 Web 應用程式，採用敏捷開發模式，從超薄 MVP 開始逐步迭代。

### 核心功能
1. **讀經計劃管理** - 設定聖經讀經進度和每日計劃
2. **獎勵機制** - 完成每日讀經後的小遊戲/獎勵
3. **社交分享** - 與朋友分享進度和讀經感想
4. **問問牧者** - 私密訊息功能，可詢問小組長或牧師

### 技術架構
- **後端**: Django 5 + DRF + Django Channels
- **前端**: Django Templates + HTMX + Tailwind CSS
- **資料庫**: SQLite (MVP) → PostgreSQL (生產環境)
- **部署**: SSH + Gunicorn (MVP) → Docker Compose (生產環境)

## 里程碑規劃

### 🎯 **Milestone 0.1: 超薄 MVP** (1-2 天)
**目標**: 建立最小可行產品，驗證核心讀經打卡循環

**範圍**:
- 單人使用（無社交功能）
- 固定讀經計劃（一週詩篇 1-7）
- 基本打卡 + 心得功能
- 簡單完成獎勵（徽章顯示）
- Ask 牧者表單（非即時）
- SQLite + 單節點部署

**完成定義 (DoD)**:
- 在遠端機器上可啟動服務
- 用戶能完成「今日打卡 + 心得 + 看到徽章」流程
- Ask 表單送出可在管理頁面看到記錄
- 有完整的 README 部署說明

---

### 🎯 **Milestone 0.2: 可設定讀經計劃** (2-3 天)

- 自訂開始日期

**技術改進**:
- 資料模型擴充
- 管理介面優化
- 基本的資料遷移機制

## 風險與應對

### 技術風險
- **資料庫遷移**: 提前規劃 SQLite → PostgreSQL 遷移路徑
- **即時通訊**: WebSocket 複雜度，可考慮先用輪詢

### 範圍風險  
- **功能膨脹**: 嚴格控制每個 milestone 的範圍
- **過度設計**: 保持 MVP 思維，先求可用再求完美

### 部署風險
- **環境差異**: 早期在目標環境測試
- **資料備份**: 從 MVP 階段就建立備份機制
